# 07_2. フォーメーション＆可変システム・アルゴリズム (Formation & Dynamic Shape Logic)

## 1. 設計思想：フォーメーションとは「静的な点」ではなく「動的な箱（スロット）」である

現実のサッカーにおいて、「4-3-3」などの表記は単なるキックオフ時の初期配列（電話番号）に過ぎない。実際の試合中、陣形はボールの位置（3サード）と局面（可変フェーズ）、さらに「選手の役割（ロール）」と「チーム戦術（マクロ）」の掛け合わせによって常に可変（トランスフォーム）する。

本エンジンは上位AIが全体の陣形を強制的に統制するのではなく、**ボトムアップ型AI（Utility AI）による自己判断と連携**を採用している。フォーメーションの可変ロジックも、以下のプロセスによって**「創発的に（自然と）」形成される**。

### ボトムアップによる「創発的可変」と初期フォーメーションの関係性

1.  **アンカー（基準点）の保持:**
    各選手は、マスターデータで定義された「フォーメーション上の初期スロット（担当レーン・階層）」と「ケミストリーリンクで繋がっている味方」を、自身の評価関数の絶対的な基準点（アンカー）として保持する。
2.  **Utility AIによる自律評価:**
    試合中、各選手は毎Tick、以下の要素を組み合わせて行動スコアを計算する。
    *   自身の**「役割（ロール）」**による行動バイアス（例：インバーテッドSBは中央への移動スコアが高い）。
    *   **「チーム戦術プロトコル（07_3参照）」**によるリスク許容度と連動スイッチ。
    *   **「空間認識（FOV）」**で得られた敵味方の位置情報や「空いたスペース」の検知。
    *   リンクを持つ味方からの**「メッセージング」**（例：`Msg_SpaceCreated`、`Msg_RequestSwap`）。
3.  **創発的な陣形形成（玉突き補完）:**
    一人の選手がロールに従って移動（例：サイドバックがオーバーラップ）し、「空席（空きスロット）」ができると、周囲のリンクされた味方のAIがそれを検知する。結果として、**『空いたスロットを埋める行動（カバー）』や『最終ラインの枚数を調整する行動（レストディフェンス）』のスコアが跳ね上がり、玉突き的に連鎖移動が発生する**。
    これにより、上位AIの命令なしに、状況に合わせて `3-2-5` や `5-4-1` などのダイナミック・シェイプが創発的に完成する。

## 2. 局面×ゾーン別：ダイナミック・シェイプ（可変フェーズ定義）

すべてのフォーメーションは、6つのシチュエーション別フェーズに対する目標構造を持つ。ポジティブ/ネガティブ・トランジション（攻守の切り替え）は、これらフェーズ間の移行期間（特定のアクションスコアが急激に変動・スパイクする期間）として機能する。

### 2.1 ボール保持時 (In Possession) の3段階

ピッチのX軸（前後・ボールの進行度）に応じ、攻撃時の個人評価スコアの重点は以下の3段階にシームレスに遷移する。

1.  **Phase A: ビルドアップ（自陣サード / GK保持〜相手第1プレッシャーライン突破まで）**
    *   **目的:** 相手の1stプレス（FW/MF）に対して「＋1の数的優位（主に3バック化またはGK参加の4枚）」を作り、中盤の選手と**トライアングル（三角形）**を形成して前進の出口を作る。
    *   **アルゴリズム:** 相手FWの枚数（$N$人）を検知し、最終ラインのビルドアップ関与人数が $N+1$ 人になるよう、CDMの降下（サリーダ・ラボルペ）、片側SBの絞り（偽3バック）、またはGKの列上げの行動スコアが自律的に上昇する。
2.  **Phase B: プログレッション（ミドルサード前進）**
    *   **目的:** 5レーンにバランスよく人を配置し、ライン間（相手MFとDFの間）のハーフスペースに縦パスの受け手を立たせる。
    *   **アルゴリズム:** ボールサイドのSB・CM・W（またはSH）のAIが、常に互いに菱形または三角形の距離感（12m〜18m）を維持するよう、自身の基準座標をオフセットするスコア補正をかける。
3.  **Phase C: ファイナルサード侵入＆押し込み（敵陣深く・フィニッシュワーク）**
    *   **目的:** 相手の守備ブロック（4枚または5枚）をピン留めするため、前線の5レーンすべてに1人ずつ（計5人）を配置し、後方にフィルター（2〜3人）と最終ライン（2〜3人）を残す（`3-2-5` または `2-3-5` 構造の創発）。
    *   **フィニッシュワーク連動:** ボールがペナルティエリア脇（ポケットや大外）に侵入した瞬間、前線5レーンのうち逆サイドの選手・中央の選手にそれぞれ「ニア飛び込み」「ファー詰め」「マイナス（バイタル）待機」のターゲット空間へのランスコアが割り振られる。

### 2.2 ボール非保持時 (Out of Possession) の3段階

相手のボール位置と自チームの戦術に応じ、守備行動の評価基準は以下の3段階に可変する。

1.  **Phase D: ハイプレス（敵陣でのビルドアップ妨害）**
    *   **目的:** 相手のパスコースを消し、特定のサイドへ誘導してハメる。
    *   **アルゴリズム（カバーシャドウと縦スライド）:**
        *   1stディフェンダー（主にCF）が「特定のパスコースを背中で消す（カバーシャドウ）」弧を描く軌道でプレスのスコアを高める。
        *   連動し、ボールサイドの味方（WGやCM）が1列前へ**縦スライド**して相手をロックするスコアが跳ね上がる。逆サイドの選手は中央へ絞る。
2.  **Phase E: ミドルブロック（中盤でのゾーンディフェンス）**
    *   **目的:** 縦横のコンパクトネス（最終ラインから最前線まで25m〜30m以内）を保ち、中央への縦パスを封鎖する。
    *   **アルゴリズム:** 各DF・MF選手は、ボールが存在するレーンと隣接する2レーンの計3レーンに向かって横スライドするスコア補正を受け、逆サイドの大外レーンを意図的に捨てる配置を創発する。
3.  **Phase F: ローブロック / リトリート（自陣撤退・押し込まれ時）**
    *   **目的:** ペナルティエリア内およびポケット（ハーフスペース奥）の空間を物理的に埋め尽くし、シュートコースとクロスを遮断する。
    *   **アルゴリズム（ライン吸収による5バック・5ミッド化）:**
        *   相手がアタッキングサードに侵入すると、中盤の底（CDM）の「CB間に吸収される」スコア、または両翼（WB/SH/W）の「1列降りる」スコアが強制的に高まる。結果として、4-3-3であっても **`5-4-1` や `4-5-1` の多層ブロックへ自動的に移行**する。

## 3. 「フォーメーション × 選手役割（ロール）」の合成（玉突き）アルゴリズム

フォーメーションが定義した「箱（スロット）」に対し、選手の不変の「役割（ロール）」を当てはめた結果、ボトムアップでどのように配置が確定していくかのプロセス。

### 3.1 5レーン×3階層の「スロット占有」
攻撃時（Phase B〜C）、ピッチ前方は以下の概念的スロットを持つ。
*   **第1階層（最前線・5レーン）：** `[L-Out]`, `[L-Half]`, `[Center]`, `[R-Half]`, `[R-Out]`
*   **第2階層（中盤ピヴォット・フィルター）：** `[Pivot-L]`, `[Pivot-C]`, `[Pivot-R]`
*   **第3階層（後方リスク管理・3バック/2バック）：** `[Back-L]`, `[Back-C]`, `[Back-R]`

### 3.2 玉突き可変（ローテーション）の解決手順
各エージェントのUtility AIが以下の順序で高いスコアを出し、パズルが解決される。

1.  **Step 1（最前線のロール優先配置）:**
    *   CFと両Wが「ロール」に応じた第1階層スロットへ向かう。
    *   *例:* 左Wが「インサイドFW」なら `[L-Half]` を占有。結果として、左の大外 `[L-Out]` が空間検知により「空席（空きスペース）」と認識される。
2.  **Step 2（2列目・SBのロールによる空席補充）:**
    *   CM、CAM、SBが、Step 1で生まれた空席や第2階層の枠を埋める行動スコアを高める。
    *   *例:* `[L-Out]` が空席のため、左SB（攻撃的SB）が第3階層から第1階層まで一気に押し上がるスコアが最大化。これに伴い、左CMはバランスを取るため1列下がり `[Pivot-L]` を埋める。
3.  **Step 3（後方レストディフェンスの3枚維持ルール）:**
    *   第3階層の選手（CBや残ったSB/CDM）は、チーム戦術が「超攻撃」でない限り、最終ラインに3人の選手を残す（3バック化）カバーリングのスコアが優先される。
    *   *例（サリーダ・ラボルペ）:* 両SBとも高く上がった場合、CDM（アンカー）が2人のCB間に降りる行動スコアが最大化し、`[RCB - CDM - LCB]` の3バックを形成する。

## 4. 具体例：『4-3-3』における全可変パターンの定義モデル

本エンジンでは、**フォーメーションごとにドキュメントを作成せず、後述するマスターデータ（JSON等）で構造を定義する。** 以下は「4-3-3」を適用した場合の、AIの自律判断による可変モデルの代表例である。

### 4.1 初期スロットとケミストリーリンク
*   **スロット:** `GK`, `RSB`, `RCB`, `LCB`, `LSB`, `CDM`, `RCM`, `LCM`, `RW`, `LW`, `CF`
*   **主要リンク線（連携のアンカー）:**
    *   左トライアングル: `LSB - LCM - LW` （＋ `LCB - LSB`, `LCB - CDM - LCM`）
    *   右トライアングル: `RSB - RCM - RW` （＋ `RCB - RSB`, `RCB - CDM - RCM`）
    *   中央ライン: `RCB - LCB - CDM`, `RCM - LCM - CF`, `RW - CF - LW`

### 4.2 局面別の可変挙動（創発結果）
*   **【保持・ビルドアップ時（自陣）】**
    *   **創発形 `3-1-4-2` または `2-3-2-3`:**
    *   相手2トップのプレスを検知し、CDMがCB間に降りて3バック化（または片側SBが残る）。
    *   残りの選手がリンク線を基準にひし形・三角形の距離を保ち、ボール保持者へ3つのパスコースを提供する。
*   **【保持・敵陣押し込み時（アタッキングサード）】**
    *   **創発形 `3-2-5`（王道バランス型）：**
    *   前線5レーン：左から `LSB(大外) - LW(内側) - CF(中央) - RCM(内側) - RW(大外)`（※ロールにより埋まるレーンは入れ替わる）。
    *   中盤2枚：`LCM - CDM` がバイタルエリア手前でネガトラの網を張る。
    *   後方3枚：`LCB - CDM(降下) - RCB` などのレストディフェンス。
*   **【非保持・相手ビルドアップへのハイプレス時】**
    *   **創発形 `4-1-3-2（非対称スライド）`:**
    *   1. `CF` が相手CBへアプローチしつつ、背中で横パスを切る。
    *   2. 逆側CBへボールが出た瞬間、同サイドの `CM` が縦スライドプレスのスコアを最大化し飛び出す。
    *   3. リンクで連動し、ボールサイドの `W` は相手SBを監視、逆サイド `W` は中央へ絞る。`CDM` は前へ出てスペースを埋める。
*   **【非保持・押し込まれ時（自陣ローブロック）】**
    *   **創発形 `5-4-1`（ポケット封鎖型）：**
    *   相手の深い侵入を検知し、`CDM` の最終ライン吸収スコアが最大化（5バック化）。
    *   両翼（`RW`, `LW`）が中盤まで完全に降りるスコアが高まり、第2ラインを形成。`CF` 1枚のみがカウンター起点として残る。

## 5. マスターデータ定義構造（Schema）

4-3-3以外の全てのフォーメーション（4-4-2, 3-5-2等、計15種以上）は、以下のデータ構造（JSONスキーマ等）に従ってマスターデータとして定義される。エンジンはこれを読み込み、ボトムアップで可変ロジックを回す。

```json
{
  "formation_id": "4-3-3",
  "name": "4-3-3",
  "slots": [
    // 11枠分のスロット定義
    {
      "slot_id": "LCB",
      "position_category": "CB",
      "base_matrix": { "lane": "L-Half", "tier": "Defensive" }, // 基準となるPitch Matrix割り当て
      "base_coordinates": { "x": 0.25, "y": 0.35 } // 相対的な初期基準座標 (例: 0.0~1.0)
    },
    // ... 他10スロット
  ],
  "chemistry_links": [
    // 結線グラフ（連携のアンカーとなる線）
    { "from": "LCB", "to": "LSB" },
    { "from": "LCB", "to": "CDM" },
    { "from": "LSB", "to": "LCM" }
    // ... 他のリンク
  ]
}
```

この「11個のスロットの初期位置・階層」と「リンクのネットワーク」さえ定義されていれば、あとはAIが各々のロールと戦術プロトコルに従ってスコアを計算し、自動的に可変やプレス連動が機能する。

## 6. セットプレー＆リスタート配置ロジック (Set-Pieces & Restarts)

インプレーのフォーメーション座標とは独立した、リスタート専用の配置アルゴリズム。**「その時点でのピッチ上11人の能力値（Physical, Speed, Pass, Shoot等）」をソートして動的に役割（スポット）を割り当てる。**

### 6.1 キックオフ配置 (Kick-off)
*   **マイボール時:** CFがセンタースポット。CM/CAMがサポート位置。戦術が「ハイプレス/カウンター」時は、片方のWとSBがタッチライン際最前線に立ち、奇襲のロングボールを狙う配置をとる。
*   **相手ボール時:** 全員が自陣ハーフ内にコンパクトな陣形（縦幅15m以内）で待機し、プレス誘導のスイッチを伺う。

### 6.2 ゴールキック配置 (Goal Kick)
*   **ショートビルドアップ選択時（ポゼッション志向）:**
    両CBがPA内のGK横まで極端に開き、両SBがタッチライン際の中盤高さまで上がる。CDMがPA弧の頂点に降りてきて相手FWを釣り出す。
*   **ロングフィード選択時（カウンター志向）:**
    チーム内で最も `フィジカル` が高い前線選手（ターゲットマン）の周辺に、2列目の選手を密集（オーバーロード）させ、セカンドボール回収率を極大化させる。

### 6.3 コーナーキック配置 (Corner Kick)
*   **【攻撃時】11人の動的割り当てアルゴリズム:**
    *   `キッカー`: ピッチ上で最も `パス精度` が高い選手。
    *   `ショートコーナー要員`: キッカーに次いで `パス`・`ドリブル` が高い選手。
    *   `ターゲット群 (4〜5人)`: `フィジカル` ＋ `シュート` が高い上位陣を、「ニア」「中央」「ファー」「GK前」に割り当て。
    *   `バイタル待機 (2人)`: アーク付近に配置。ミドルシュートとクリア回収。
    *   `カウンターケア (2人+GK)`: `スピード` が最も速い選手2人をハーフウェイライン付近に残し、ロングカウンターを封じる。
*   **【守備時】ハイブリッド（ゾーン＋マンマーク）配置:**
    *   `ストーン役 (1人)`: ニアポスト手前に固定配置。
    *   `ゾーン軸 (2〜3人)`: ゴールエリア中央に `フィジカル` 上位を配置。
    *   `マンマーカー`: 相手のターゲット群に対し、対人マークを割り当てる。
    *   `バイタル埋め (1〜2人)`: ペナルティエリア角とアーク付近をケア。
    *   `カウンター起点 (1人)`: 最も `スピード` が高い選手（WやCF）を前線に残す。

### 6.4 フリーキック＆スローイン配置
*   **直接FK（ゴール前）:** 壁の枚数（3〜5枚）を距離と角度に応じて自動算出。GKの弾きに詰めるストライカーを配置。
*   **スローイン:** ボール位置から半径20m以内に、近場の3人を集結させ、数的優位を作ってからリスタートする。
